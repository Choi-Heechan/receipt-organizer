# 영수증 정리 플러그인 (receipt-organizer) 설계

작성일: 2026-10-20

## 1. 의도와 이유

회사에서 여러 사람이 사용한 영수증(PDF·이미지)을 사람별 폴더에 모아 두면, 경리 책임자가 필요한 시점에 Claude에게 "영수증 정리해줘"라고 말하는 것만으로
사람별 엑셀, 전체 합계 엑셀, 그리고 한눈에 보는 웹 화면(HTML)이 만들어지게 한다.

이것을 Claude Code 플러그인으로 만들어 공개 GitHub 저장소(마켓플레이스)에 올리고, 지인들이 각자 PC의 Claude에서 설치해 쓰게 한다.

현재 사용자 PC에 있는 `receipt-processor` 스킬(동기화된 개인 스킬)이 이 엑셀 형식의 원형이다. 이번 플러그인은 그것을 기반으로 하되,
지인 배포가 가능하도록 의존성을 줄이고 대시보드·JSON 출력을 추가한 후속판이다.

## 2. 사용 장면

1. 경리 책임자가 작업용 상위 폴더를 만들고, 그 아래에 개인 폴더를 둔다. 각 개인이 자기 폴더에 영수증 파일을 넣는다.
   ```
   영수증_2026년10월/          ← 실행 시 이 경로를 지정
   ├── 홍길동/
   │   ├── 20261003_택시.jpg
   │   └── 20261005_식당.pdf
   └── 김철수/ ...
   ```
2. 경리 책임자가 Claude에서 "영수증 정리해줘 /path/영수증_2026년10월" 처럼 상위 폴더를 지정해 실행한다. (폴더는 반드시 사용자가 지정한다. 자동 탐색하지 않는다. 지정이 없으면 경로를 묻는다.)
3. Claude가 개인 폴더를 하나씩 처리하여 개인별 엑셀을 만들고, 전부 끝나면 합계 엑셀·JSON·대시보드 HTML을 만든다.
4. 채팅에 폴더별 처리 파일 수와 합계 금액, 총합계, 오류 건수를 표로 보고하고 생성 파일 경로를 알려 준다.
5. 경리 책임자는 `dashboard_YYYYMMDD.html`을 더블클릭해 브라우저에서 확인한다.

## 3. 목표

- 상위 폴더 아래 각 하위 폴더(개인)의 `.jpg .jpeg .png .pdf` 파일을 Claude의 시각 읽기(Read 도구)로 판독한다. 하위 폴더 안의 더 깊은 폴더도 포함하여 그 개인의 파일로 취급한다.
- 출력은 모두 상위 폴더 바로 아래에 저장한다(YYYYMMDD = 실행일).
  - `receipt_<폴더명>_YYYYMMDD.xlsx` — 개인별
  - `list_receipt_YYYYMMDD.xlsx` — 합계
  - `receipt_YYYYMMDD.json` — 전체 결과 데이터
  - `dashboard_YYYYMMDD.html` — 웹 화면
- 엑셀 형식은 제공된 샘플(`PDF_test/` 의 3개 파일)과 동일하게 한다(아래 5장).
- 채팅 완료 보고에 폴더별 파일 수·합계 금액을 표시한다.
- 지인이 GitHub 계정 없이 설치할 수 있다.

## 4. 비목표 / 안티 목표

- **서버 없음.** Railway 등 외부 서버로 전송하지 않는다. 영수증 데이터는 PC 밖으로 나가지 않는다(안티 목표: 데이터가 외부로 전송되는 것).
- ChatGPT/Codex 지원은 이번 범위가 아니다. 별도 프로젝트로 나중에 만든다. 단 JSON 출력은 그때 재사용할 수 있게 둔다.
- 대시보드에 차트(결제수단 비율·날짜 추이)는 첫 버전에 넣지 않는다.
- 회계 소프트웨어 연동, 경비 승인 흐름, 중복 영수증 탐지는 하지 않는다.
- 안티 목표: 지인 PC에서 추가 설치(pip 패키지, LibreOffice 등)를 요구해 설치에 실패하는 것.

## 5. 출력 형식 (샘플 기준, 확정)

### 개인별 엑셀 `receipt_<폴더명>_YYYYMMDD.xlsx`
시트 1개. 1행 머리글, 1행 고정(freeze).

| 열 | 머리글 | 내용 |
|---|---|---|
| A | No. | 1부터 |
| B | ファイル名 | 파일명(하위 폴더 안 깊은 곳이면 개인 폴더 기준 상대경로) |
| C | 日付 | YYYY/MM/DD. 판독 불가 시 파일명 앞 8자리 날짜가 있으면 그것, 없으면 読み取りエラー |
| D | 店名 | 상호 |
| E | 登録番号 | 인보이스 등록번호 T+13자리 |
| F | 金額（円） | 세금 포함 합계 정수 |
| G | 消費税率 | 10% / 8% / 複数税率 |
| H | 支払区分 | 現金・クレジット・PayPay・iD・QRコード 등 |

- 판독 못 한 칸은 `読み取りエラー` 문자열, 빨간 배경(FFE0E0)·빨간 글씨.
- 마지막 행 `合計` + 금액 열 SUM 수식.
- 열 너비: 6 / 32 / 14 / 32 / 20 / 14 / 14 / 20. 머리글 진한 파랑(1F4E79) 흰 글씨, 줄무늬 행(D6E4F0), 합계 행 연노랑(FFF2CC). (기존 `receipt-processor/scripts/create_excel.py`의 스타일)

### 합계 엑셀 `list_receipt_YYYYMMDD.xlsx`
열: No. / サブフォルダ名 / ファイル数 / 合計金額（円） / エラー件数 / 出力ファイル名, 마지막 행 `合計` + SUM.
- エラー件数 = 읽기 오류 칸이 하나라도 있는 영수증 수.
- 合計金額 = 금액을 읽은 영수증만 합산.

### JSON `receipt_YYYYMMDD.json`
```json
{
  "generated_at": "2026-10-20T15:30:00+09:00",
  "root_folder": "영수증_2026년10월",
  "totals": {"folders": 2, "files": 11, "amount": 117116, "errors": 2},
  "folders": [
    {"folder": "株式会社A", "file_count": 7, "total_amount": 44768, "error_count": 1,
     "output_file": "receipt_株式会社A_20261020.xlsx",
     "receipts": [{"no":1,"filename":"...","date":"2025/05/01","store":"...","reg_no":"T...",
                   "amount":6050,"tax_rate":"10%","payment":"クレジット"}]}
  ]
}
```
읽기 오류 값은 문자열 `"読み取りエラー"`.

### 대시보드 `dashboard_YYYYMMDD.html` (사용자가 시안 B 선택)
- 단일 HTML 파일. 데이터는 HTML 안에 내장(file:// 로 열어도 동작, 인터넷·CDN 불필요).
- 상단: 총금액 · 총 건수 · 읽기 오류 건수.
- 본문: 폴더(사람)별 카드 — 이름, 합계 금액, 건수, 오류 수. 금액 큰 순 정렬(빌더 판단, 변경 가능).
- 카드 클릭 시 해당 폴더의 영수증 목록(날짜·상호·금액·결제수단, 필요 시 등록번호·세율)이 펼쳐짐. 읽기 오류는 빨간 표시.
- 시안: `.superpowers/brainstorm/*/content/dashboard-layout.html` 의 B.

## 6. 제약

- Claude Code 플러그인 형식. 플러그인 안에 스킬 1개(트리거: 「영수증 정리」「영수증 처리」「領収書処理」「領収書をまとめて」 등 한국어·일본어).
- 판독은 Claude 자체(Read 도구)로 한다. 외부 OCR API 키를 요구하지 않는다.
- 파일 생성 스크립트는 **Python 3 표준 라이브러리만** 사용한다(openpyxl 등 pip 설치 불필요). xlsx는 zip+XML을 직접 작성. LibreOffice recalc 단계 없음 — SUM 수식에 계산된 값도 함께 기록.
- 배포: 사용자의 공개 GitHub 저장소 = 마켓플레이스. 지인은 `/plugin marketplace add <계정>/<저장소>` → `/plugin install` 으로 설치(계정 불필요).
- 영수증 1파일 = 영수증 1장으로 가정.

## 6-1. 설계자 판단으로 정한 것 (사용자 검토 대상)

- **공개 저장소와 테스트 데이터**: 실제 영수증(PDF_test 샘플 포함)과 그 결과물은 저장소에 커밋하지 않는다. 저장소의 테스트·예시는 합성 데이터만 사용. 실제 샘플 폴더는 로컬 수동 검증에만 쓴다. `.gitignore`에 `.superpowers/` 와 출력 파일 패턴 추가.
- **같은 날 재실행**: 같은 이름 파일이 이미 있으면 덮어쓰지 않고 `_2`, `_3` … 접미사를 붙인다(예: `receipt_홍길동_20261020_2.xlsx`). 4종 파일 모두 같은 접미사로 맞춘다. 파일이 열려 있어 쓸 수 없으면 해당 파일명을 알려 주고 닫은 뒤 다시 실행하도록 안내한다.
- **폴더 구조 예외**: 지정 폴더에 하위 폴더가 없고 파일만 있으면 그 폴더 자체를 1명으로 처리한다. 하위 폴더와 함께 상위 폴더에 직접 놓인 영수증 파일은 처리하지 않고 완료 보고에 "처리 안 된 파일"로 나열한다. 영수증 파일이 0개인 하위 폴더는 건너뛰고 보고한다. 지원하지 않는 확장자(HEIC 등)는 건너뛴 파일로 보고한다.
- **대시보드 화면 언어**: 일본어 UI(사용자 결정). 영수증 내용(상호·결제수단 값)은 판독 그대로.
- **확인 필요(要確認) 표시** (사용자 결정): 판독은 했지만 확신이 낮은 값(흐림·겹침·손글씨, 금액과 세액 계산이 안 맞음, 등록번호 자릿수 불일치 등)은 값을 그대로 넣고 `要確認` 표시를 붙인다.
  - 엑셀: 해당 칸 노란 배경(FFF2A0). 시트 오른쪽에 `備考` 열을 추가해 어느 항목이 왜 要確認인지 짧게 적는다.
  - 합계 엑셀: `要確認件数` 열 추가(エラー件数 옆).
  - JSON: 영수증마다 `"needs_review": ["amount", ...]`, `"note": "..."`, 폴더·totals에 `review_count`.
  - 대시보드: 카드에 要確認 건수, 목록에서 노란 표시.
  - 要確認 값은 합계 금액에 포함한다(読み取りエラー는 제외).

## 6-2. 실행 환경 (사용자 결정: Python + 첫 실행 시 자동 확인·설치 안내)

지인 PC는 Windows가 Mac보다 많다. 파일 생성 스크립트는 Python 3 표준 라이브러리만 사용하고, 스킬 시작 시 Python 확인 단계를 둔다.

1. Python 탐지: Windows는 `py -3` → `python` → `python3` 순으로 시도하고, `--version`이 실제 3.x를 반환하는지 확인한다(Microsoft Store 스텁 `python3` 오탐 방지). Mac은 `python3`.
2. 있으면 그 실행 명령을 기억해 이후 단계에서 사용한다.
3. 없으면 처리 전에 일본어로 안내하고 동의를 받는다:
   - Windows: `winget install Python.Python.3.12` (동의 시 Claude가 실행, 또는 사용자가 직접 실행). 설치 후 새 터미널/세션에서 PATH 반영이 필요할 수 있음을 안내하고 재탐지한다.
   - winget 불가 시: python.org 다운로드 안내 + 「Add python.exe to PATH」 체크 안내.
   - Mac: `xcode-select --install` 또는 macOS가 띄우는 개발자 도구 설치 창 안내.
4. 같은 안내를 README(한국어·일본어)에 기재한다.
5. 스크립트는 Windows 경로(역슬래시, 일본어·공백 포함 폴더명)와 UTF-8을 고려한다. 데이터는 명령행 인자 대신 임시 JSON 파일 경로로 전달한다(Windows 명령 길이·인코딩 문제 회피).

## 7. 사용자가 결정한 것

- 트리거는 경리 책임자의 실행 요청, 상위 폴더 경로는 직접 지정.
- 엑셀 형식은 제공 샘플과 동일.
- 완료 후 폴더별 파일 수·합계 금액 표시.
- Railway 서버 생략, 로컬 HTML 대시보드로 대체.
- Claude 전용. ChatGPT 판은 별도.
- 대시보드는 사람별 카드형(B), 화면 언어는 일본어.
- 잘못 읽었거나 확인이 필요한 값은 要確認으로 표시.
- 지인 PC는 Windows가 다수.
- Python(표준 라이브러리만) + 첫 실행 시 자동 확인·설치 안내 방식.
- 공개 GitHub 저장소로 배포해도 됨.

## 8. 빌더에게 맡기는 것

- 플러그인·저장소 이름(가칭 `receipt-organizer`), 디렉터리 구조, 스크립트 분할.
- 대시보드 시각 디자인 세부.
- 판독 프롬프트 문구, 원호(令和) 변환 등 판독 요령(기존 SKILL.md 참고).
- 테스트 방법(샘플 폴더 `~/sample-receipts` 사용 가능).
